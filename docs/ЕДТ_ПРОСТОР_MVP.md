# Единый документ требований к ИТ-решению PROSTOR MVP

## 1. Назначение

MVP объединяет два сценария из ТЗ хакатона в один рабочий процесс:

1. **ИИ-агент умного поиска** — принимает запрос на естественном языке, рекомендует продукт/услугу, исполнителей, аналоги и связанные услуги.
2. **Умный конструктор ТЗ** — превращает выбранный результат поиска в черновик `RequestDraft`, проверяет полноту, риски, ограничения договоров и формирует пакет документов.

## 2. Роли пользователей

- **Заказчик / инициатор заявки** — описывает потребность, уточняет объект, сроки и исходные данные.
- **Методолог / куратор ТЗ** — проверяет структуру, риски и готовность пакета.
- **Руководитель / аналитик** — смотрит статистику по продуктам, рискам и потенциальной упаковке услуг.

## 3. Функциональные требования

### 3.1 ИИ-агент умного поиска

- Ввод запроса в свободной форме.
- Определение намерения: поиск услуги, подбор исполнителя, поиск аналогов, генерация ТЗ.
- Ранжирование продуктов по ключевым словам, операциям, расценкам, договорам и аналогам.
- Объяснение, почему продукт найден.
- Рекомендация потенциальных исполнителей с учетом доступных договоров и рейтинга.
- Показ аналогичных выполненных работ.
- Рекомендации по оформлению заявки.
- Переход в конструктор ТЗ с предзаполненными данными.

### 3.2 Умный конструктор ТЗ

- Автоматический выбор шаблона и структуры по продукту.
- Заполнение ключевых полей: объект, заказчик, цель, срок, исходные данные, 3D-модель, субподряд.
- Автоматический набор этапов из пресета продукта.
- Расчет процента готовности.
- Выявление рисков:
  - не указан объект;
  - нужна 3D-модель, но нет подтвержденных исходных данных;
  - нужна 3D-модель без этапа подготовки данных;
  - нарушены ограничения субподряда;
  - для субподряда нужен отдельный расчет стоимости.
- Рекомендации по исправлению рисков.
- Структурированный результат проверки: критичность, код замечания, пояснение и действие для исправления.
- Безопасная смена шаблона с сохранением заполненных одноимённых разделов.
- Сравнение сроков и индикативной стоимости выполнения работ по каждому доступному подрядчику.
- Экспорт пакета: `Приложение 1. ТЗ.docx`, `Приложение 2. КП.xlsx`, `Приложение 3. РС.xlsx`.

### 3.3 Аналитика

- Сводные показатели по продуктам, компаниям, договорам и историческим кейсам.
- Популярные продукты.
- Частые риски и ошибки заявок.
- Основа для выявления типовых связок услуг и кандидатов на упаковку продуктов.

## 4. Нефункциональные требования

- Backend: FastAPI.
- Frontend: React + Vite.
- API-first взаимодействие между интерфейсом и сервисами.
- Локальный запуск без внешней LLM для стабильной демо-версии.
- Детерминированные правила для демонстрации ключевого кейса "подсчет запасов + 3D".
- Возможность дальнейшего подключения LLM и полнотекстового/векторного поиска.
- DeepSeek используется для диалога и инженерных формулировок; правила готовности и денежные расчёты остаются детерминированными.
- При недоступности внешней LLM сохраняется офлайн-fallback.

## 5. API

- `GET /api/health` — проверка доступности.
- `POST /api/search/query` — поиск продукта, исполнителей и аналогов.
- `POST /api/drafts/from-search` — создание черновика ТЗ из результата поиска.
- `POST /api/drafts/evaluate` — пересчет готовности и рисков.
- `POST /api/drafts/export` — формирование ZIP-пакета DOCX/XLSX.
- `POST /api/assistant/chat` — контекстные подсказки ассистента.
- `GET /api/analytics/overview` — аналитическая сводка.
- `POST /api/tz/{id}/validate` — детальная валидация ТЗ.
- `POST /api/tz/{id}/switch-template` — смена шаблона.
- `GET /api/estimates/products/{id}` — сравнение сроков и стоимости подрядчиков.
- `GET /api/assistant/status` — состояние LLM-провайдера.

## 6. Критерии приемки MVP

- Запрос "Нужно оценить запасы по объекту..." приводит к продукту "Подсчёт запасов / ПТД".
- Система показывает причины выбора, исполнителей и аналоги.
- По нажатию "Сформировать ТЗ" открывается конструктор с предзаполненным черновиком.
- При включении 3D-модели без готовых исходных данных появляются риски и рекомендации.
- Процент готовности меняется при заполнении обязательных полей.
- Экспорт скачивает ZIP с DOCX и XLSX-файлами.
- Раздел аналитики открывается из интерфейса.

## 7. Ограничения MVP

- Поиск реализован гибридными эвристиками, без промышленного векторного индекса.
- Каталог продуктов в коде сжат до демо-ядра, но ориентирован на выгрузку из системы.
- Стоимость в РС формируется как демонстрационная оценка-заготовка.
- Экспорт не заменяет юридическую проверку финального ТЗ.
